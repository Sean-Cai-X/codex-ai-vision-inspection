BUSINESS INTEGRATION
1. In the existing review action, collect a human-confirmed issue and copy only
   the contract's allowlisted fields. Do not serialize a complete case object.
   project_ref/case_ref/sample_ref are opaque IDs, not paths or filenames.
   selected_candidates contain ID, class, score and original-image pixel bounds
   [xmin,ymin,xmax,ymax] only, not full outlines. Do not reuse box display position
   as a mask-boundary quality measurement.
2. source_split comes from the frozen dataset version. Annotation version and SHA
   describe the annotation actually used. A later annotation is a new version;
   unlabelled VERIFY has null GT-dependent metrics. Confirmed target absence can
   have count metrics but no invented geometric IoU or boundary distance.
3. Keep original issue JSON bytes immutable. Compute SHA256 over those bytes,
   including whitespace and newline. Export preview and human approval remain
   required: free-text checks catch common paths/URIs but cannot prove that prose
   contains no private information. Text is conservatively bounded in UTF-8 bytes.
4. ParseStrict rejects duplicate keys, malformed JSON, oversized input and excessive
   depth. ValidateRecord(issue, contract, "issue") rejects unknown fields at EVERY
   defined object level and enforces truth, failure and count consistency.
5. R&D replies with issue_id and the exact exported issue SHA. States:
   received / located / needs_diagnostics / reproduced / fix_pending_retest.
   received means an actual receipt has occurred, not merely reading a NOT_SENT
   business ticket. needs_diagnostics asks only for allowlisted numeric/semantic
   categories. reproduced requires a synthetic evidence digest; it does NOT
   establish independent business generalization.
6. A repair-binding is an EXTERNAL companion record referencing the final
   immutable handoff.lock.json SHA. Do not put this lock-referencing companion
   into that same lock's hash coverage (circular dependency). Independently
   deliver its own SHA or authenticated record, and cross-check every declared
   model/runtime/capability against the package's verified manifests.
7. ValidateRecord for each record, then ValidateLinks using the original issue
   byte SHA. fix_pending_retest requires a validated repair-binding with the same
   issue ID+SHA and lock SHA. A hash field's presence is not cryptographic trust
   or proof that a referenced file exists: importer must independently verify
   the actual lock, contents, lineage, dependencies and ABI before execution.
8. Business resolves issue_id to the ORIGINAL local sample/annotation/parameters;
   fail explicitly on missing association. No filename fallback, cross-project
   fallback, automatic latest selection or automatic activation. Human retest
   concludes resolved/partially_resolved/unresolved/new_issue. The R&D disposition
   intentionally cannot close a business issue.

RD3 DIAGNOSTIC SEMANTICS
- above_threshold = examined + unexamined; examined = suppressed + selected;
  selected = returned + mask_rejected. Use null for uncomputed quantities.
- cap_hit is the detection-selection cap, not a claim about model precision.
  cap-hit or unexamined candidates means full_post_nms_count stays null. Seven
  raw class counts describe RETURNED candidates before project class filtering.
- Existing runtime/typed ABI has NOT been extended in this step. Business must
  leave unavailable counters null, not fill zeros or infer full counts from a
  capped list. Wiring true runtime counters/version metadata is the next step.
