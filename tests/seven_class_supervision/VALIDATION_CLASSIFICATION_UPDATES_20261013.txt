Actual classification-head updates and per-level gradient audit, 2026-10-13

Conclusion: the v13 classifier update/optimizer/checkpoint chain is intact.
Gradient and hard-background allocation are strongly uneven across scales.
This is a diagnostic replay, not a new accepted model or a proven learning-rate
fix. Model-quality acceptance remains false. Business defaults and deliveries
are unchanged. Local native C++/LibTorch only; no Python or gateway execution.
Only registered parent assets and frozen R&D synthetic assets were consumed.

What was measured
-----------------
Replay the COMPLETE v13 circle and ellipse training: same parent, seed 20261012,
80 frozen paired_coverage_v1 Train exposures per shape, 40 updates, two size-1
microbatches per update, Adam 1e-4 -> 1e-6 cosine, decay 0, train BN and eval
validation. VERIFY never used for training. Same class/box/DFL/mask owners and
same v13 objective/decoder. Original source/parent inventories checked unchanged.
No training policy or threshold was changed by this task.

The actual head module's tensor identities identify its cv3 parameters.
Backbone C2f blocks also contain a cv3; substring-only whole-model selection
would misidentify them. Each classifier parameter must require gradients and
belong to exactly one optimizer group. This audit checks 24 parameter tensors
per model (eight per P3/P4/P5 branch), including the three final seven-channel
convolution weights/biases. Production classification grouping was inspected
and already uses model.22.cv3/m22.cv3; no grouping bug was found there.

For EVERY microbatch, autograd.grad obtains:
- foreground CE gradients;
- ordinary background sigmoid BCE gradients;
- weighted hard-background gradients (factor 2 already included).
Inputs include the live head outputs AND registered classifier parameters;
these are parameter gradients, not detached-output proxy gradients alone.
Diagnostic autograd.grad is checked not to change accumulated .grad buffers.
The actual normal loss.backward() still supplies optimizer gradients.
Two microbatches accumulate at scale 1/2, exactly matching the original run.

The audit compares the accumulated true classifier gradients with the component
sum; then records each actual Adam step, moments, LR, nonzero gradient/update
counts, update norms, update/parameter norm ratios and seven-channel terminal
bias values. Actual positive/hard-anchor selections are retained in loss Terms;
they are NOT inferred from whether a gradient happens to be zero.

Training negatives are reported separately as outside every GT box versus
unassigned anchors inside a GT box. The latter include unselected anchors near
the true target; they must not be described as all true background pixels.

Update/serialization results
----------------------------
Both shapes: 24 classifier parameter tensors x 40 updates = 960 observations.
No missing/zero accumulated classifier gradients; no zero parameter updates.
Every classifier parameter has Adam state and reaches actual Adam step 40.
LR is recorded from optimizer groups, not reconstructed solely for display.

All parameters AND buffers after replay equal the frozen v13 reference exactly:
changed state tensors = 0, maximum state delta = 0, for both models.
Saved/reloaded replay states also have maximum delta 0. Checkpoint file SHA256
is identical to the frozen reference for both shapes. Thus the audit did not
alter training and the recorded updates were preserved by serialization.

Float32 decomposition verification: max relative L2 gaps observed are
3.40965e-6 (circle), 3.41463e-6 (ellipse). Separate convolution backwards change
floating-point summation order, so element-wise relative comparison near zero
was inappropriate. Both L2 gap and max gap are bounded by 1e-6 absolute plus
1e-4 times the corresponding actual-gradient norm. Gaps/bounds are recorded.
The test deliberately corrupts a real classifier gradient and verifies rejection.
The final replay/state/checkpoint equality is exact, not this tolerance test.
