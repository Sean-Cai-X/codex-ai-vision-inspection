Dense classification supervision - native development trial, 2026-10-09

Implemented
Business loss version: center_dense_balanced_bce_v2.
For every feature level, classification targets cover all anchors and all seven
channels. Existing target-center assignment remains; other anchors are negative.
Classification loss = mean BCE of positive anchors + mean BCE of background
anchors, then mean across levels. Each group has weight 1; empty groups contribute
zero. This prevents the dense background count from diluting the positive loss.
Box, DFL and mask losses retain their previous center-anchor assignment/weights.
This is deliberately NOT a claim of complete task-aligned assignment support.
Same-class center duplicates are idempotent; conflicting classes at one center
are rejected rather than silently overwriting targets. Current business datasets
are single-project-class, so cross-class collisions are outside that input scope.
Classification channel IDs remain arc=0,circle=1,ellipse=2,line=3,open_curve=4,
polygon=5,closed_curve=6. Thresholds, NMS and class order were not altered.

Reproduction

in ../build_supervision_runtime (Release); retain process-local Torch/OpenCV PATH.
Runner keeps its prior four arguments (binding, parent root, rules, output base).
Optional final arguments are epochs iterations; defaults 2 2, diagnostic bounds
1..200 with iterations >= epochs. For this overfit diagnostic append: 20 40.
Total iterations are optimizer updates, divided across epochs; an epoch is NOT
automatically a dataset pass. Only this 20/40, two-image, batch-1 setup happens
to visit both Train samples once per epoch. All actual values enter the receipt.

VALIDATION_PARENT_COMPARISON_20261009.txt. Never overwrite an existing run.
